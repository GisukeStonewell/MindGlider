# 検証記録

検証日：2026-11-02。Windows 11 x64、Rust 1.99.1、egui／eframe 0.31.1、wgpuバックエンド。

Visual C++ランタイムは静的リンクし、配布EXEのインポート先がWindowsのシステムDLLのみであることを確認しました。

## 完了した検証

- Rustの型検査とClippy（`-D warnings`）。サンドボックスの増分キャッシュでハードリンクを使えない場合は、ファイルコピーに切り替わる環境由来の通知が出ます。
- 自動テスト32件：編集・循環拒否・Undo／Redo、未知XMLとHTMLの保持、装飾・画像倍率・ノート・リンク・条件の往復、Freeplane由来の3マップ、バックアップ10世代、AIの範囲・競合・不正応答、プロセス終了・キャンセル・タイムアウト、復元後の未保存状態。
- UIのショートカットと、日本語IMEイベントの未確定文字→確定文字の置換を回帰テスト。
- 実画面で日本語の表示、ノード追加、通常キー入力、保存、起動・終了を確認。
- 100％・125％・200％のアプリ内表示倍率で描画し、画像を確認。OSの表示倍率設定自体は変更していません。
- TXT・Markdown・OPML・PNG・JPEG・SVG・PDF・HTMLの生成。PDFはPopplerで画像へ変換し、日本語と描画内容を確認。複数ページPDFのページ数も検証。
- 実際のCodex CLI：生成したツリーに子ノードを1個追加し、自動反映とUndoによる復元を確認。約7.94秒。
- Freeplaneの作業ツリーに変更がないことを確認。

## 性能

## 0.9.0 の改名とFreeplane読み込み互換性（2026-11-02）

- プロジェクトをmindgliderへ移動。Rustパッケージ・バイナリー・構造体・ウィンドウタイトル・翻訳・アイコンファイル・Windowsリソース・配布名・スクリプト・既存出力のファイル名をMindGlider系の名前へ変更。旧状態ファイルはartifacts/legacy-stateへ保管し、元のプロジェクトフォルダーは残していない。Freeplaneクローンは変更していない。
- 旧マップの専用メタデータと画像寸法を読み込み、新規保存では新しい識別子に統一。旧環境変数は読み込み専用の互換経路として残す。旧識別子の文字列はcompatモジュールとその回帰テストに限って保持する。
- ユーザー指定のMindmap.mmの先頭がXML宣言であることを確認。Freeplane MFileManager.loadTreeImplは先頭1000バイトを直接MapVersionInterpreterへ渡し、knowsが `<map version="…` のstartsWith判定をするため、宣言があるとDEFAULTのunknownApp／unknownURLへ進む。宣言・BOMを付けず、version属性を先頭にして警告条件を除去した。
- Freeplaneの読み書きはUTF-8。そのためShift_JISにはせず、useAsciiCharset／XMLWriter.writeEncodedと同じ方針で本文・属性値の非ASCII文字をXML数値文字参照にした。非ASCIIのCDATAは意味が等しいエスケープ済みテキストにし、注釈・未知のXML名は保持する。
- 74件のテスト（ライブラリー22、UI補助13、CLI8、コア31）が成功。先頭属性の順序、日本語・アクセント文字・絵文字・改行・特殊文字・ノート・詳細・CDATA・未知XML・旧メタデータ／画像寸法の読み込みを検証。Clippy -D warningsも実施。
- 実際のFreeplane MapVersionInterpreter.java、mapVersions.xml、関連JavaソースをJDK 22でコンパイルし、修正版がFREEPLANE1_12_1、anotherDialect=false、needsConversion=falseと判定されることを確認。JavaのUTF-8 ReaderとXMLパーサーでも元の本文とリッチコンテンツが一致した。
- 元のDownloads/Mindmap.mmは変更せず、artifacts/compat-0.9/Mindmap-fixed.mmに修正版コピーを作成。新しいアプリ名のGUIと、このコピーの表示画像をartifacts/ui-0.9へ記録。Freeplane GUI本体での操作試験は未実施。
- 配布するExample.mmはパッケージ作成時に毎回生成し、古いXML宣言付きファイルを再配布しない。
